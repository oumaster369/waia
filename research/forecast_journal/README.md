# Журнал прогнозов

Это отдельный Python-пакет. Он скачивает публичную историю бессрочных USDT-свопов HTX, на каждом закрытом баре считает признаки только из того, что уже было известно, записывает прогноз и потом сверяет его с тем, что произошло на самом деле.

Платных API нет. Ключ биржи не нужен. Вселенная ровно такая: BTC, ETH, SOL, XAU, USOIL, DOGE, XRP, BNB, HYPE, ZEC, ADA, LTC, SUI, FIL, TRX, PEPE, LINK, BRENTOIL.

Зависимости: numpy, pandas, matplotlib, pyarrow. Если pyarrow нет, кэш пишется в CSV. sklearn не обязателен: бустинг включается флагом `--with-gbm`, только когда пакет установлен.

## Команды

Из корня репозитория, после `pip install -r research/forecast_journal/requirements.txt`:

```bash
# Скачать историю. 4h/1h/15m — с 2021-01-01 до текущего момента.
# Минутки — с 2024-01-01: на них проверяется, что раньше случилось, стоп или цель.
python -m research.forecast_journal backfill \
  --data-dir research/forecast_journal/data_cache \
  --from 2021-01-01 \
  --timeframes 4h,1h,15m \
  --workers 6

# Посчитать WAIA-S на сетке 1h и 15m, горизонт удержания 24h.
# Если на последних 20% времени у WAIA-S нет значимо положительного матожидания,
# пакет сам прогоняет заранее объявленный набор формул и логистическую регрессию.
python -m research.forecast_journal historical \
  --data-dir research/forecast_journal/data_cache \
  --decisions 1h,15m \
  --horizon 24h \
  --report-dir research/forecast_journal/reports

# Один проход «сейчас»: дописать прогноз и закрыть те, у которых горизонт уже прошёл.
python -m research.forecast_journal live --once

# Живой цикл каждые 15 минут. Журнал дописывается, повторный запуск те же id не дублирует.
python -m research.forecast_journal live --interval 15 \
  --liquidity-url http://127.0.0.1:8080
```

`--liquidity-url` необязателен. Клиент ходит в `{url}/api/liquidity?symbol=BTC`. Если адреса нет, группа ликвидности просто пустая: веса WAIA-S перенормируются без компоненты L, расчёт не падает.

Отчёты лежат в `research/forecast_journal/reports/`: `waia_s.md`, `waia_s.json`, `search.md`, `search.json`, `accuracy.md`, `accuracy.json` и PNG в `figures/`. Сырые свечи и журнал в `data_cache/` и `journals/` в git не коммитятся.

На чистой машине, с `--timeframes 4h,1h,15m --workers 6`, загрузка 18 инструментов с 2021-01-01 заняла около 20 минут (свечи плюс фандинг, OI, индекс, базис). Один запрос к HTX здесь отвечает примерно за 1.3 секунды. Минутки с 2024 года в этот прогон не входили: это ещё около 1000 запросов на инструмент и только уточняет путь стоп/цель, не удлиняет историю решений. Сам `historical` на этой машине (652 тысячи часовых строк, поиск из 28 формул) занял около 10 минут. Отчёт этого прогона: `reports/waia_s.md` и `reports/search.md`.

Тесты, без сети:

```bash
python -m unittest discover -s research/forecast_journal/tests -v
```

## Откуда цифры

HTX, `api.hbdm.com`, публичные методы:

- свечи 1m / 15m / 1h / 4h, страницами не длиннее ~1400 баров;
- история ставки фандинга, постранично, у BTC она уходит в 2020-е;
- открытый интерес — биржа отдаёт только последние 200 точек на период, глубже нельзя;
- индекс — только последние `size` баров (до 2000), параметр `from/to` биржа игнорирует;
- официальный базис — около 200 последних баров;
- доля лонгов/шортов у «элиты» — около 30 последних точек.

Старый базис, где индекс уже есть, считается самим пакетом: `(цена свопа − индекс) / индекс` на последнем баре индекса, который закрылся не позже момента решения.

OKX (ликвидации и OI) пробуется и при отказе просто пропускается. В этой среде публичный OKX часто отвечает 403. Признака из OKX в истории почти нет, и отчёт это показывает отдельной группой, а не подставляет ноль как будто данные были.

Минутные свечи до 2024 года пакет по умолчанию не тянет: их слишком много, а для признаков хватает 15m/1h/4h. Путь сделки (коснулись входа, стопа, цели) идёт по минутке, если она есть в кэше, иначе по 15m. В одном баре, если задеты и стоп, и цель, засчитывается стоп.

## Никакого будущего

Момент решения t — это время закрытия бара. В признаки попадают только бары с `close_time <= t`, последний фандинг с `funding_time <= t`, последний OI и индекс с меткой не позже t.

Свеча, которая ещё не закрылась, не используется. Лимитный вход WAIA-S не может исполниться на той же свече, по которой посчитали сигнал: её low случился до закрытия.

Метки «что было дальше» (доходность, максимум, минимум) считаются отдельно и в признаки не кладутся. Обучающая строка попадает в обучение, только если её горизонт уже закончился до начала тестового куска. Это и есть embargo: перекрывающиеся будущее и тест выкидываются.

Проверка в `tests/test_pit.py`: портятся все свечи и фандинг после t, признаки на t не меняются.

## Формула WAIA-S

Обозначения. `clip` — обрезка в отрезок [-1, 1]. ATR — Wilder, 14 баров. Наклон EMA20 — изменение за один бар, делённое на ATR.

Компонента тренда T — среднее из четырёх чисел:

- clip( (цена − EMA50 4h) / ATR 4h / 2 )
- clip( (цена − EMA200 4h) / ATR 4h / 2 )
- clip(наклон EMA20 4h в единицах ATR)
- направление 4h

Направление 4h само среднее из: наклона EMA20, clip( (EMA20 − EMA50) / ATR / 2 ) и clip( (цена − VWAP 4h) / ATR / 2 ). VWAP 4h — за 6 баров, то есть за сутки.

Компонента потока M — среднее из:

- направления 15m (наклон EMA20 15m, положение цены к EMA20 и к VWAP 15m, всё в ATR);
- clip(CVD за час / оборот за час). Настоящего taker-buy в свечах HTX нет, поэтому CVD — это сумма оборота, подписанного положением закрытия внутри бара: +1 у хая, −1 у лоя;
- дисбаланс стакана, если пришёл живой ответ `/api/liquidity`. В истории его нет, и он не подменяется чем-то другим.

Компонента позиционирования P, со знаком «против толпы»:

- −clip(z-score фандинга / 3). z-score считается по последним 90 начислениям, не по будущим;
- −clip(базис / 0.002);
- −clip(long/short − 1), только если есть свежий elite-print. Иначе этот член не входит в среднее.

Компонента ликвидности L — магнит. Вверх минус вниз по кластерам ликвидаций на 0.5% / 1% / 2% / 3%, веса 0.4, 0.3, 0.2, 0.1, затем tanh, и среднее с дисбалансом ближайших стен. В истории L нет.

Веса: T 0.30, M 0.25, L 0.30, P 0.15. Если компоненты нет, её вес выкидывается, остальные делятся на сумму оставшихся, чтобы снова получилась 1. На истории без L это 0.30/0.70, 0.25/0.70, 0.15/0.70.

Q — доля обязательных кусков, которые реально посчитались, среди активных компонент. Обязательные: четыре куска T, два куска M (15m и CVD), два куска P (фандинг и базис). Необязательные (стакан, long/short, весь L) при отсутствии Q не уменьшают. Если базиса нет, а всё остальное есть, Q = 7/8.

Итог:

S = 100 · tanh(взвешенная сумма) · Q

Сделка:

- лонг, если S ≥ 40 и T ≥ −0.3;
- шорт, если S ≤ −40 и T ≤ 0.3;
- вход лимиткой: цена ∓ 0.3 · ATR 1h (лонг ниже, шорт выше);
- стоп: на 0.5 · ATR 1h за экстремумом последних 24 часовых баров;
- цель: ближайшая из двух, у которой чистый RR ещё не меньше 1.8 — противоположный экстремум тех же 24 баров или 2 · ATR от входа;
- если такой цели нет, карточка не выставляется.

RR после комиссии: (расстояние до цели минус комиссия на вход и на цель) / (расстояние до стопа). Комиссия по умолчанию 0.05% с каждой стороны, тейкер HTX. В R по факту та же формула, только вместо цели — фактическая цена выхода. Неисполненный лимит даёт R = 0 и до конца горизонта новый сигнал по этому инструменту не ставится: книга занята.

Функция, которую можно вызвать снаружи:

```python
from research.forecast_journal.models.best_signal import signal
score, side, card = signal(features)
# score — число S, side — "long" | "short" | "flat", card — dict или None
```

Пока поиск не выбрал другую формулу на окне разработки, `signal` — это WAIA-S. Если выбрал, константа `SELECTED` в `models/best_signal.py` указывает на неё. Выбор делается до холдаута. Холдаут в выбор не входит.

## Как устроена проверка

Время режется один раз по календарю, одинаково для всех инструментов.

- последние 20% — холдаут. Его не используют, чтобы выбрать формулу или коэффициент регуляризации;
- из первых 80% последние 30% — окно сравнения кандидатов;
- первые 70% окна разработки — чтобы выбрать L2 у логистической регрессии.

WAIA-S ни на чём не подгоняется: пороги 40 и 1.8 заданы заранее. Для неё холдаут — честная проверка одной гипотезы. Поиск других формул запускается только если на холдауте среднее R не положительно при одностороннем p < 0.05 и хотя бы 30 карточках. Это занижает, а не завышает шанс «найти» формулу: если кусок рынка был тяжёлым для WAIA-S, он же достанется и остальным.

У поиска формулы тоже заранее написаны, пороги не крутятся по холдауту. Их список и текст — в `search.md`. Поправка на множественные сравнения — Benjamini–Hochberg по p-value окна сравнения. Deflated Sharpe (Бейли и Лопес де Прадо) считается по Шарпу на сделку и по разбросу Шарпов всех испытанных формул: он отвечает на вопрос «этот Шарп всё ещё выглядит большим, если помнить, сколько формул мы перебрали?».

Логистическая регрессия: L2 из {0.1, 1, 10} выбирается по log loss внутреннего куска. На окне сравнения коэффициенты переоцениваются каждые 14 дней только по прошлому. На холдауте одна заморозка на границе. В признаки не входят будущая доходность и сама сделка.

## Что значат метрики

**Expectancy R, unfilled = 0.** Среднее R по всем выставленным карточкам. Неисполненный лимит — ноль, не «сделки не было, выкинем». Это ответ на вопрос «что будет, если каждый раз ставить эту карточку, когда инструмент свободен».

**Expectancy R, filled only.** То же среднее, но только по тем, кого цена добрала. Удобно смотреть, есть ли край после входа, но это уже не матожидание политики «ставь лимитку».

**Hit rate filled.** Доля исполненных сделок с R > 0. Это не то же самое, что «цель раньше стопа»: плюс бывает и на выходе по времени.

**Target first / stop first.** Доля исполненных, где первой случилась цель или стоп. Остаток — выход по концу горизонта.

**Fill rate.** Доля карточек, до которых цена дошла.

**p-value.** Односторонний t-тест «среднее R > 0» по карточкам политики (нули включены). Сделки не перекрываются по времени внутри инструмента, поэтому обычный t-тест здесь уместнее, чем тест по каждому часу. Порог значимости в этом пакете: среднее > 0, p < 0.05, карточек не меньше 30. Мало сделок — значимости нет, даже если среднее красивое.

**Sharpe.** Среднее R / стандартное отклонение R, на одну карточку, без пересчёта в «годовых». Годовой Шарп из редких сделок легко нарисовать любым множителем; здесь он не используется.

**Brier.** Среднее (прогноз P(up) − факт)^2. Факт = 1, если цена через горизонт выше, иначе 0. Ноль — идеал, 0.25 — это вечный прогноз 50/50. Меньше 0.25 — лучше монетки. Считается по всем барам с конечным S, не только по сделкам.

**Log loss.** То же, но логарифм: сильно наказывает уверенный прогноз, который не сбылся. Вероятности обрезаются в (1e-6, 1−1e-6), чтобы логарифм не взорвался.

**Hit rate вероятности.** Доля баров, где знак (P − 0.5) совпал со знаком будущей доходности. P ровно 0.5 пропускается.

**Сырая вероятность.** P = (clip(S, −100, 100) / 100 + 1) / 2. S = 40 даёт P ≈ 0.70. Это не калибровка, а просто шкала.

**Изотоника и Платт.** Отдельное отображение «S → вероятность», построенное только на прошлом (walk-forward, раз в 30 дней, с embargo). Изотоника — неубывающая лестница. Платт — логистическая регрессия исхода на одно число S. В отчёте три Brier рядом: сырой, изотоника, Платт. Если калибровка не улучшает Brier, шкала S не несёт дополнительной частоты.

**Надёжность (reliability).** По корзинам прогноза: средняя заявленная P и фактическая частота роста. На диагонали прогноз честный. Картинка `figures/waia_s_reliability.png`.

**Покрытие квантилей.** Например, 10% квантиль будущей доходности, оценённый по прошлому, должен накрывать около 10% реализаций. Сильный недобор или перебор значит, что распределение «как раньше» не держится.

**Корзины S.** Таблица: в каких диапазонах S какая фактическая частота роста и какое среднее R сделок. Если корзина S > 40 не растёт чаще, чем корзина около нуля, порог 40 ничего не отделяет.

**Абляция.** Та же формула, но одна компонента вынута из суммы, веса и Q пересчитаны. Порог по T остаётся прежним, иначе «убрали T» просто обнулило бы все сделки фильтром. Сравнивать надо среднее R, а не красоту S.

**По символу, месяцу, сессии, режиму волатильности.** Сессии без перекрытия, UTC: Азия [0, 8), Европа [8, 16), США [16, 24). Режим волатильности — ATR 1h против своих скользящих квантилей 33% и 66%, квантили только из прошлого. Если плюс сидит в одном месяце или одном символе, это не устойчивость.

**Группы признаков.** Для каждой группы считается доля строк, где она есть, и Brier с ней и без неё. Ликвидность на истории отсутствует — это видно как fraction = 0, а не как нулевой вклад. Так же отдельно видно, что OI и elite-ratio покрывают только хвост истории.

**Lift признака.** Порог — медиана на раннем куске. На следующем куске смотрим, насколько P(up) выше медианы отличается от базовой частоты. q-value — Benjamini–Hochberg по всем проверенным колонкам. Маленький q значит «это не первый попавшийся из сорока столбцов». Это не готовое правило для торговли.

## Живой режим

`live` дописывает JSONL. Идентификатор прогноза — хеш от символа, времени, сетки, горизонта и модели. Повторный запуск тот же id пропускает. Реальность дописывается отдельной строкой, когда горизонт уже в прошлом, и тоже один раз. Битая строка в файле пропускается, файл не переписывается.

Каждый проход обновляет `reports/live_accuracy.md`: сколько прогнозов, сколько реальностей, среднее R, доля прибыльных среди исполненных.
