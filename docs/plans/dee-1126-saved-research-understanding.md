## 4. Exact result and refusal rules

No blanket catch maps failures to UNAVAILABLE. Only known typed data/operational states become declared results; unexpected calculation, storage, decode, membership, constraint or infrastructure failures propagate and exit nonzero without a new completion.

- Valid canonical AVAILABLE lane, fully verified and explicitly admitted source/revision: categorical TRUSTED in the narrowly scoped evidence projection; existing score/freshness gate still decides sufficiency.
- Correct saved lane with a valid source/revision **not listed** in the assignment: categorical UNTRUSTED, stable reason `RESEARCH_SOURCE_REVISION_NOT_ADMITTED`, original data retained. This is a research configuration rejection, not a factual accusation about the provider. Never confuse a wrong observed revision with a corrupt claimed revision: the latter is an integrity error.
- Valid non-AVAILABLE canonical/acquisition outcome, missing normalized required lane or unresolved trust: declared UNKNOWN/unassessed lane in the sidecar; no invented observation/trust ID and no padded evidence record. The existing gate sees the missing available candidate. A source record cannot become TRUSTED merely because its score is1.
- Malformed/mismatched/foreign/future/unsealed/duplicate/unsupported input, changed raw input under an old seal, normalization mismatch, source-body/revision binding mismatch or caller-supplied authority/result: whole-command typed integrity/configuration refusal; no new completion or fallback evidence. Known reasons remain distinct.
- Stale/low-score data with otherwise admitted lineage retains TRUSTED category and exact score/time, then follows the existing gate's INSUFFICIENT result; no auto-demotion or threshold rewrite. Required contradiction controls retain the existing INSUFFICIENT/CONFLICTED behavior with1118 integrated. V1's generated NONE/null concerns only its finite single-record identity-consistency assessment; it does not assert that a general market contradiction detector ran. Cross-timeframe directional disagreement is the existing alignment input, not secretly reclassified as contradictory evidence. An unsupported supplied contradiction assessment is refused, never discarded.

A terminal valid research completion always retains the exact gate and all12 artifact outputs. Its separate completion disposition is:

1. `COMPLETED_SUPPORTED`: receipt SUFFICIENT, WHAT claim SUPPORTED, actual raw WHAT `ANSWERED` and answer not UNCLEAR.
2. `COMPLETED_UNRESOLVED`: all other valid completed computations, including insufficient/unavailable/partial/conflicted results or raw PARTIAL/UNCLEAR. This advances only the research interpretation prefix, not a positive-evidence count or any authority.

The existing exact builder can return claimState SUPPORTED when the receipt is sufficient while the raw bridge returns PARTIAL/UNCLEAR. Preserve both verbatim; the second disposition prevents representing that as a positive resolved result. Likewise one missing lane can yield PARTIALLY_SUPPORTED despite an UNAVAILABLE overall receipt. Do not rewrite the artifact into a cleaner-looking status. Native acceptance must explicitly show both cases.

The CLI reports `COMPLETE` only when every requested sequence has a durable terminal interpretation and separately reports supported/unresolved counts. An incomplete range, missing source, busy/lost lease, incompatible replay, authorization/integrity error or timeout exits nonzero with the exact reason; a completed range of unresolved research observations is process success but never positive readiness. It does not poll/wait for absent future source packets.
